- ✅ مؤشرات SLA ملونة (أخضر/أصفر/أحمر)
- ✅ عارض المرفقات مع التحميل

## 🎯 المميزات الرئيسية

### 1️⃣ إجراءات الموافقة/الرفض
**كيف يعمل:**
```
1. انقر على زر 🟢 (موافقة) أو 🔴 (رفض) في عمود "الإجراءات"
2. يظهر مربع تأكيد مع تفاصيل الطلب
3. للرفض: يجب إدخال سبب الرفض (إلزامي)
4. للموافقة: يمكن إضافة ملاحظات (اختياري)
5. بعد التأكيد: الطلب يُزال من الجدول فوراً + تحديث الإحصائيات
```

**متى تظهر الأزرار:**
- ✅ الحالة: `SUBMITTED`, `PENDING`, `UNDER_REVIEW`
- ✅ الصلاحية: المستخدم لديه صلاحية الموافقة
- ❌ الحالات الأخرى: الأزرار لا تظهر

**APIs المستخدمة:**
```
POST /api/claims/{id}/approve
POST /api/claims/{id}/reject
POST /api/pre-approvals/{id}/approve
POST /api/pre-approvals/{id}/reject
```

---

### 2️⃣ مؤشرات SLA
**الألوان:**
- 🟢 **أخضر (آمن):** أكثر من يومين متبقيين
- 🟡 **أصفر (تحذير):** يومان أو أقل متبقيين
- 🔴 **أحمر (متأخر):** تجاوز الموعد النهائي

**النصوص:**
- "3 يوم" - 3 أيام متبقية
- "اليوم" - ينتهي اليوم
- "متأخر 2 يوم" - متأخر بيومين

**الحساب:**
```javascript
الحد الأقصى: 3 أيام عمل
المتبقي = 3 - (اليوم - تاريخ الإنشاء)
```

**ملاحظة:** الحساب الحالي يستخدم الأيام التقويمية، يمكن تحسينه لاحقاً لاستخدام أيام العمل من Backend.

---

### 3️⃣ عارض المرفقات
**كيف تفتحه:**
1. انقر على أيقونة 📎 (مرفقات) في عمود "الإجراءات"
2. يفتح Drawer من الجانب الأيمن

**المحتوى:**
- 📄 قائمة المرفقات:
  - اسم الملف
  - نوع الملف (شارة)
  - حجم الملف (KB)
  - زر تحميل ⬇️

**التحميل:**
- انقر على أيقونة ⬇️ بجانب أي ملف
- يبدأ التحميل فوراً
- يعمل لكل من المطالبات والموافقات المسبقة

**الحالة الفارغة:**
- "لا توجد مرفقات لهذا الطلب" (رسالة info)

**APIs المستخدمة:**
```
GET /api/claims/{id}/attachments
GET /api/claims/{id}/attachments/{attachmentId}
GET /api/pre-approvals/{id}/attachments
GET /api/pre-approvals/{id}/attachments/{attachmentId}
```

---

### 4️⃣ تفاصيل التكاليف المالية
**متى يظهر:**
- ✅ **للمطالبات فقط** (Claims)
- ❌ لا يظهر للموافقات المسبقة

**المحتوى:**
داخل Drawer المرفقات → Accordion قابل للتوسيع:
```
┌─────────────────────────────────────┐
│ 💰 التفاصيل المالية               │
├─────────────────────────────────────┤
│ المبلغ المطلوب:      500.00 د.ل   │
│ تحمل المريض:          50.00 د.ل   │
│ الصافي للمقدم:       450.00 د.ل   │ ← بلون مميز
└─────────────────────────────────────┘
```

**API المستخدم:**
```
GET /api/claims/{id}/cost-breakdown
```

## 🔐 الصلاحيات (RBAC)

**القواعد:**
- ✅ عرض الصفحة: يتطلب صلاحية `VIEW_APPROVALS_DASHBOARD`
- ✅ عرض أزرار الموافقة/الرفض: يتطلب `canApprove()` = true
- ✅ تنفيذ الإجراءات: Backend يتحقق من الصلاحيات مرة أخرى

**التحقق الحالي:**
```javascript
const canApprove = () => {
  // حالياً: إذا المستخدم يرى الصفحة = يمتلك صلاحية الموافقة
  // مستقبلاً: يمكن التحقق من roles محددة (APPROVER, MEDICAL_REVIEWER)
  return true;
};
```

## 📊 عمود الإجراءات (Actions)

**الأزرار (من اليسار لليمين):**
```
┌────────────────────────────────────────┐
│ 📎 المرفقات │ 👁️ التفاصيل │ ✅ موافقة │ ❌ رفض │
└────────────────────────────────────────┘
```

**التفاصيل:**
1. **📎 عرض المرفقات** (info):
   - يفتح Drawer المرفقات
   - متاح دائماً

2. **👁️ عرض التفاصيل** (primary):
   - ينقل إلى صفحة التفاصيل الكاملة
   - متاح دائماً

3. **✅ موافقة** (success):
   - يفتح مربع تأكيد الموافقة
   - متاح فقط للحالات: SUBMITTED, PENDING, UNDER_REVIEW
   - متاح فقط إذا `canApprove() = true`

4. **❌ رفض** (error):
   - يفتح مربع إدخال سبب الرفض
   - متاح فقط للحالات: SUBMITTED, PENDING, UNDER_REVIEW
   - متاح فقط إذا `canApprove() = true`

## 🔄 التحديثات الفورية (Optimistic UI)

**عند الموافقة/الرفض:**
```
1. المستخدم ينقر "تأكيد الموافقة"
2. الطلب يُزال من الجدول فوراً (قبل انتظار Backend)
3. رسالة نجاح تظهر: "✅ تمت الموافقة على المطالبة بنجاح"
4. الإحصائيات العلوية تتحدث تلقائياً
5. إذا فشل Backend: رسالة خطأ + إعادة تحميل البيانات
```

**الفائدة:**
- ⏱️ تجربة مستخدم سريعة
- 📱 استجابة فورية
- 🔄 تحديث تلقائي للبيانات

---

## ⚠️ قواعد التحقق (Validation)

| القاعدة | التطبيق |
|---------|---------|
| ❌ لا يمكن الرفض بدون سبب | ✅ حقل نصي إلزامي + `required` + تحقق قبل الإرسال |
| ❌ لا يمكن الموافقة بدون تحميل البيانات | ✅ البيانات تُحمل عند فتح مربع الموافقة |
| ❌ الإجراءات لا تظهر لغير المخولين | ✅ `canApprove()` + RBAC Guard |
| ✅ SLA مرئي وملون | ✅ شارات ملونة (Green/Yellow/Red) |
| ✅ المرفقات قابلة للعرض والتحميل | ✅ Drawer + زر تحميل |

## 🎨 الألوان والأيقونات

### الحالات (Status):
- 🟡 **SUBMITTED** → warning (أصفر)
- 🔵 **UNDER_REVIEW** → info (أزرق)
- 🟢 **APPROVED** → success (أخضر)
- 🔴 **REJECTED** → error (أحمر)

### SLA:
- 🟢 **Safe** → success (أخضر) - أكثر من يومين
- 🟡 **Warning** → warning (أصفر) - يومان أو أقل
- 🔴 **Breach** → error (أحمر) - متأخر

### الأيقونات:
- 📎 `AttachFileIcon` - مرفقات
- 👁️ `ViewIcon` - عرض
- ✅ `ApproveIcon` (ThumbUp) - موافقة
- ❌ `RejectIcon` (ThumbDown) - رفض
- ⬇️ `DownloadIcon` - تحميل
- ⚠️ `WarningIcon` - تحذير SLA
- ❗ `ErrorIcon` - تجاوز SLA
- ✔️ `CheckIcon` - SLA آمن

## 🛠️ استكشاف الأخطاء

### المشكلة: الأزرار لا تظهر
**الحل:**
1. تحقق من حالة الطلب (يجب أن تكون SUBMITTED, PENDING, أو UNDER_REVIEW)
2. تحقق من صلاحيات المستخدم
3. افتح Console وتحقق من `canApprove()`

### المشكلة: لا يمكن تحميل المرفقات
**الحل:**
1. تحقق من اتصال الإنترنت
2. افتح Console وتحقق من استجابة API
3. تأكد من وجود مرفقات فعلاً (backend)

### المشكلة: SLA غير صحيح
**الحل:**
- الحساب الحالي يستخدم أيام تقويمية
- للحصول على أيام عمل دقيقة، انتظر التكامل مع Backend API

### المشكلة: التحديثات لا تظهر
**الحل:**
1. أغلق الصفحة وافتحها مجدداً
2. امسح cache المتصفح
3. تحقق من استجابة API في Network tab

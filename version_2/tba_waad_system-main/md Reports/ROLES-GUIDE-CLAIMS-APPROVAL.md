## 🎯 الأدوار المتاحة للموافقة والرفض على المطالبات

### الإجابة السريعة:

لمنح صلاحية **الموافقة والرفض على المطالبات**، اختر أحد هذين الدورين:

| الدور | الموافقة/الرفض | الاستخدام الموصى به |
|------|----------------|---------------------|
| **REVIEWER** | ✅ نعم | ⭐ **موصى به** - مراجع طبي متخصص فقط |
| **INSURANCE_ADMIN** | ✅ نعم | للمدراء الإداريين في شركة التأمين |

---

## 📋 تفاصيل كل دور

### 1️⃣ **REVIEWER** (مراجع طبي) ⭐ الأنسب للموافقة/الرفض

**الوصف:**  
دور متخصص للمراجعين الطبيين الذين مهمتهم مراجعة المطالبات الطبية فقط.

**الصلاحيات:**
```javascript
✅ VIEW_CLAIMS         // عرض المطالبات
✅ APPROVE_CLAIMS      // الموافقة على المطالبات
✅ REJECT_CLAIMS       // رفض المطالبات
```

**مميزات هذا الدور:**
- ✅ صلاحيات محددة ومركزة فقط على المراجعة
- ✅ لا يستطيع إنشاء أو تعديل المطالبات
- ✅ لا يستطيع الوصول لصلاحيات إدارية أخرى
- ✅ **الأنسب لفريق المراجعة الطبية**

**متى تستخدمه؟**
- ✅ موظف في قسم المراجعة الطبية
- ✅ طبيب مراجع
- ✅ متخصص تقييم المطالبات
- ✅ أي شخص مهمته فقط الموافقة/الرفض

**مثال:**
```
د. محمد أحمد - مراجع طبي
الدور: REVIEWER
المهمة: مراجعة المطالبات الطبية والموافقة/الرفض فقط
```

---

### 2️⃣ **INSURANCE_ADMIN** (مدير شركة التأمين)

**الوصف:**  
دور إداري شامل لمدراء شركة التأمين.

**الصلاحيات الكاملة:**
```javascript
// إدارة الأعضاء
✅ MANAGE_MEMBERS
✅ VIEW_MEMBERS

// إدارة المطالبات (شاملة)
✅ MANAGE_CLAIMS       // إدارة كاملة
✅ VIEW_CLAIMS         // عرض
✅ APPROVE_CLAIMS      // موافقة
✅ REJECT_CLAIMS       // رفض

// إدارة الزيارات
✅ MANAGE_VISITS
✅ VIEW_VISITS

// التقارير
✅ VIEW_REPORTS
```

**مميزات هذا الدور:**
- ✅ صلاحيات إدارية شاملة
- ✅ يستطيع إدارة المطالبات بالكامل
- ✅ يستطيع إدارة الأعضاء والزيارات
- ✅ الوصول للتقارير

**متى تستخدمه؟**
- ✅ مدير عمليات في شركة التأمين
- ✅ رئيس قسم المطالبات
- ✅ مدير فرع
- ✅ أي شخص يحتاج صلاحيات إدارية واسعة

**مثال:**
```
أحمد علي - مدير عمليات
الدور: INSURANCE_ADMIN
المهمة: إدارة شاملة للمطالبات والأعضاء والزيارات
```

## 📝 كيفية تعيين الدور

### في واجهة RBAC:

1. **الانتقال إلى إدارة المستخدمين:**
   ```
   Dashboard → الصلاحيات (RBAC) → المستخدمين
   ```

2. **إنشاء مستخدم جديد أو تعديل موجود:**
   - اضغط "إنشاء مستخدم جديد"
   - أو اضغط "تعديل" على مستخدم موجود

3. **اختيار الدور:**
   - **للمراجعين الطبيين:** اختر `REVIEWER` ⭐
   - **للمدراء الإداريين:** اختر `INSURANCE_ADMIN`

4. **حفظ:**
   - اضغط "حفظ المستخدم"

## ⚠️ تحذيرات هامة

### ❌ لا تستخدم هذه الأدوار للموافقة/الرفض:

| الدور | لماذا؟ |
|------|--------|
| **EMPLOYER_ADMIN** | لديه عرض فقط، لا يستطيع الموافقة/الرفض |
| **PROVIDER** | دوره إنشاء المطالبات فقط |
| **USER** | عرض بيانات أساسية فقط |

### ✅ قاعدة ذهبية:

```
المراجع الطبي = REVIEWER
المدير الإداري = INSURANCE_ADMIN
المدير العام = SUPER_ADMIN
```

## 🔄 سير عمل المطالبات (Workflow)

### من يفعل ماذا؟

```
1. مقدم الخدمة (PROVIDER):
   ↓ ينشئ مطالبة جديدة (CREATE_CLAIM)
   ↓

2. مراجع طبي (REVIEWER):
   ↓ يراجع المطالبة (VIEW_CLAIMS)
   ↓ يوافق أو يرفض (APPROVE/REJECT_CLAIMS)
   ↓

3. مدير التأمين (INSURANCE_ADMIN):
   → يراقب العمليات (MANAGE_CLAIMS)
   → يدخل عند الحاجة للموافقة/الرفض
   → يصدر التقارير (VIEW_REPORTS)
   ↓

4. صاحب العمل (EMPLOYER_ADMIN):
   → يطّلع على المطالبات فقط (VIEW_CLAIMS)
```

## 📞 الأسئلة الشائعة

### س1: هل يمكن إعطاء مستخدم أكثر من دور؟
**ج:** ✅ نعم، يمكن تعيين عدة أدوار لنفس المستخدم.

### س2: ماذا لو أردت مراجع يستطيع أيضاً عرض التقارير؟
**ج:** أعطه دور `INSURANCE_ADMIN` بدلاً من `REVIEWER`.

### س3: هل يمكن تخصيص صلاحيات الأدوار؟
**ج:** ✅ نعم، من خلال:
```
RBAC → الأدوار → اختر الدور → إدارة الصلاحيات
```

### س4: ما الفرق بين MANAGE_CLAIMS و APPROVE_CLAIMS؟
**ج:**
- `MANAGE_CLAIMS`: إدارة كاملة (إنشاء، تعديل، حذف، موافقة، رفض)
- `APPROVE_CLAIMS`: الموافقة فقط (صلاحية محددة)

## ✅ الخلاصة

### للموافقة والرفض على المطالبات:

```
🎯 استخدم دور: REVIEWER
   - إذا كان مراجع طبي متخصص فقط

🎯 استخدم دور: INSURANCE_ADMIN
   - إذا كان مدير إداري يحتاج صلاحيات أوسع
```

### أفضل ممارسة:
```
✅ REVIEWER للمراجعين الطبيين (مستوى تنفيذي)

✅ SUPER_ADMIN للمدير العام فقط
```
